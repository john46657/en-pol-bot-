Implementierungsphasen
Das Projekt muss strikt phasenweise entwickelt werden.
Wichtig:

* Nicht mehrere große Phasen gleichzeitig implementieren.
* Jede Phase muss vollständig funktionsfähig sein, bevor die nächste beginnt.
* Nach jeder Phase müssen Tests durchgeführt werden.
* Bestehende Funktionen dürfen durch neue Phasen nicht beschädigt werden.
* Keine Platzhalter-Funktionen als „fertig“ markieren.
* Jede Phase muss mit einer kurzen technischen Dokumentation abgeschlossen werden.

PHASE 0 – Projektgrundlage
Ziel
Ein sauberes, startbares Monorepo erstellen.
Aufgaben

* pnpm Workspace einrichten
* TypeScript konfigurieren
* ESLint einrichten
* Prettier einrichten
* Turbo konfigurieren
* Docker Compose erstellen
* PostgreSQL einrichten
* Redis einrichten
* Environment-System erstellen
* `.env.example` erstellen
* grundlegende README erstellen
* gemeinsame Packages einrichten

Ergebnis
Folgende Komponenten müssen startbar sein:

* Bot
* API
* Dashboard
* PostgreSQL
* Redis

Abnahme

```
pnpm install
pnpm dev
```

muss die komplette Entwicklungsumgebung starten können.

PHASE 3 – Discord-Synchronisierung
Ziel
Das Dashboard soll direkt mit dem Discord-Server verbunden sein.
Aufgaben
Synchronisieren:

* Rollen
* Benutzer
* Textkanäle
* Voice-Channels
* Kategorien

Das Dashboard soll beispielsweise anzeigen:

```
Rolle auswählen

[ @Polizeileitung ▼ ]
```

PHASE 6 – Zentrales Permission-System
Ziel

Aufgaben

Beispiel:


Nicht nur im Frontend.

ENTWICKLUNGSREGEL
Die Phasen müssen in dieser Reihenfolge bearbeitet werden.
Eine Phase gilt erst als abgeschlossen, wenn:

1. die Funktion implementiert ist,
2. die Datenbank angepasst wurde,
3. API und Bot integriert sind,
4. das Dashboard integriert ist, sofern erforderlich,
5. Berechtigungen funktionieren,
6. Fehlerbehandlung vorhanden ist,
7. Tests vorhanden sind,
8. die Funktion praktisch getestet wurde,
9. die Dokumentation aktualisiert wurde.

Erst danach darf mit der nächsten Phase begonnen werden.
Keine Phase darf einfach als „fertig“ markiert werden, wenn nur ein UI-Mockup oder eine nicht funktionierende Platzhalterfunktion existiert.
Das Ziel ist ein tatsächlich funktionierender, produktionsfähiger Discord Polizei-RP Bot und kein reines Demo-Projekt.
